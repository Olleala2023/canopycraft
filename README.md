# CanopyCraft

Калькулятор односкатного навеса, пристроенного к дому: карта загрузки, эпюры и подбор
сечений для стропил, обрешётки, прогонов, бруса у стены и столбов.

Материалы — только два: **сосна** (СП 64.13330.2017) и **профильная труба**
(ГОСТ 30245-2003, СП 16.13330.2017). Нагрузки — СП 20.13330.2016.

## Как открыть

Три способа, все дают одну и ту же программу:

1. **Сайт.** Включите GitHub Pages: Settings → Pages → Source: *Deploy from a branch*,
   ветка и папка `/ (root)`. Через минуту расчёт будет жить по адресу
   `https://<пользователь>.github.io/canopycraft/` и обновляться при каждом push.
2. **Файл.** Откройте `index.html` двойным кликом — самодостаточная сборка,
   работает офлайн, без сервера и без установки.
3. **Локальный сервер** для разработки — см. ниже.

### Отменить и вернуть

Ctrl+Z отменяет последнее изменение, Ctrl+Y (или Ctrl+Shift+Z) возвращает; то же — кнопки ↶ ↷
в шапке. Протянутый ползунок или перетащенный столб отменяются целиком, одним шагом.
Отменяется и «Сбросить». История живёт, пока открыта страница.

### Ссылка на расчёт

Кнопка «Ссылка на расчёт» копирует адрес, в котором зашит текущий вариант: геометрия,
сечения, площадка, цены. Адресная строка обновляется сама, её можно скопировать в любой
момент. В ссылку попадают только отличия от значений по умолчанию, поэтому она короткая —
изменённая цена металла занимает 38 символов. Открыв такую ссылку, собеседник увидит
ровно ваш расчёт, даже если у него в браузере сохранён свой.

Та же ссылка и версия программы печатаются в шапке отчёта: по распечатке вариант
открывается снова, а по версии и [`CHANGELOG.md`](CHANGELOG.md) видно, менялся ли с тех
пор расчёт.

### Справка

Кнопка «Справка» в шапке и кружки `?` у отдельных полей ведут в `help/` — статьи о том,
что стоит за расчётом:

| Статья | О чём |
|---|---|
| `help/u.html` | коэффициент использования: что означает 0,85, почему за 1,0 запаса нет, что делать с каждой определяющей проверкой |
| `help/cost.html` | подбор по цене: этапы поиска, почему варианты выглядят контринтуитивно и чего подбор не считает |
| `help/site.html` | снеговой и ветровой районы, тип местности: где их взять по картам СП 20 и во что они превращаются |
| `help/frost.html` | глубина промерзания под навесом, пучинистые грунты, касательные силы пучения и что с ними делают |
| `help/braces.html` | раскрепление столбов: что такое связь, откуда берётся μ, что держит крест и как он проверяется |
| `help/snow.html` | снеговой мешок у стены: схема Б.8 СП 20 на числах, почему кровля считается в двух вариантах загружения |
| `help/limits.html` | границы применимости: что считается, что нет и какие приняты упрощения |

Это обычные статические страницы, не часть сборки. Палитру они берут из `src/ui/tokens.css` —
`npm run build` склеивает её с `src/ui/help.css` в `help/help.css`, поэтому справка не разъезжается
с калькулятором по цветам и подхватывает выбранную тему.

### Фоновая музыка

Кнопка ♪ в шапке включает фоновую музыку и показывает ползунок громкости;
выбор запоминается. Треки лежат в `assets/audio/` с именами `1.mp3`, `2.mp3`, …
(до восьми) и добавляются загрузкой через github.com — см. `assets/audio/README.md`.
Играют по кругу в случайном порядке; пропущенные номера не мешают — страница проверяет, какие
файлы есть, при первом включении. Пока их нет, кнопка так и скажет.

Имена числами не прихоть: статическая страница не может получить список файлов
в папке — на GitHub Pages нет листинга каталога, а при открытии `index.html`
двойным кликом запрещён и `fetch`. Поэтому имена заданы в коде.

Треки скачиваются только после нажатия на кнопку, так что на скорость открытия
страницы они не влияют. Автозапуск браузеры блокируют: включённая в прошлый раз
музыка подхватится при первом клике по странице. При открытии `index.html`
двойным кликом папка `assets` должна лежать рядом с ним.

Для разработки:

```bash
npm test          # тесты ядра: МКЭ против точных формул, φ против табл. 7 СП 16 и т. д.
npm run dev       # http://localhost:8080/dev.html — модульная версия, удобнее отлаживать
npm run build     # пересобрать index.html и docs/app.artifact.html
npm run smoke     # смоук-тест интерфейса в Chrome (после сборки)
```

`index.html` — сгенерированный файл. Правьте исходники в `src/`, потом `npm run build`.
Правила работы с проектом — единицы, нормы, тесты, чертежи, стили, git — в [`CLAUDE.md`](CLAUDE.md).

На каждый PR и на `main` запускается CI (`.github/workflows/ci.yml`): тесты, проверка, что
собранные `index.html`, `docs/app.artifact.html` и `help/help.css` соответствуют исходникам,
и смоук-тест интерфейса. Забыли пересобрать — проверка покраснеет и скажет, какие файлы разошлись.

Смоук-тест (`npm run smoke`, `tools/smoke.mjs`) открывает собранный `index.html` в Chrome и
проходит интерфейс целиком: вкладки, карточки сводки, детали плана и узлов, каждое поле панели,
кнопки подбора, отчёт, подбор по цене, сценарии с крестом и морозом, старую ссылку, все страницы
справки. Любое исключение или `console.error` — падение с шагом, на котором оно случилось.
Зависимостей нет: Chrome управляется по протоколу отладки через встроенный в Node 22 WebSocket.
Chrome ищется на обычных местах; другой путь — в переменной `CHROME`.
Он же проверяет светлую и тёмную темы (контраст текста) и ширину телефона 390 px (страница не
должна прокручиваться вбок) и сохраняет скриншоты вкладок в `smoke-shots/`; в CI они
выкладываются артефактом прогона.

Кроме тестов ядра есть эталонные расчёты (`tests/reference.test.js`): стропило, посчитанное
вручную по СП 20, и коэффициенты использования варианта по умолчанию. Изменение расчёта,
которое их сдвигает, объясняется в PR. `tests/palette.test.js` не даёт вписать цвет мимо
`src/ui/tokens.css`.

## Что считается

| Элемент | Схема | Проверки |
|---|---|---|
| Обрешётка | неразрезная балка, опоры — стропила | изгиб, скалывание, прогиб l/150, сосредоточенная 1 кН, допустимый пролёт под кровлю |
| Стропила | балка на 2 опорах с консолью, наклонная | изгиб, скалывание, сжатие с изгибом, устойчивость плоской формы на консоли, смятие на опоре, прогиб l/200 |
| Прогон | неразрезная балка на столбах | изгиб, срез, прогиб l/200 |
| Брус у стены | неразрезная балка на анкерах | то же + усилие на анкер, включая отрыв |
| Столбы | сжатие с изгибом, μ из схемы связей | устойчивость в двух плоскостях (φ по п. 7.1.3), сжатие с изгибом, гибкость, местная устойчивость стенки |
| Связи ряда | крест в крайнем пролёте | растяжение и гибкость диагонали, шов, добавка в столбы пролёта |
| Связи по кровле | ферма в крайней ячейке между стропилами | растяжение и гибкость диагоналей, крепление концов, крайние стропила с продольной силой |
| Фундамент | бетонный блок заданных размеров | вес против ветрового отрыва; для пучинистых грунтов — подошва ниже промерзания и касательные силы пучения (СП 22, ф. (6.35)) |

Собственный вес всех элементов участвует в расчёте нагрузок, а не добавляется задним числом:
стропила и прогоны — погонным весом сечения, обрешётка — весом на 1 м², столбы — весом ствола
в осевой силе. Массы выводятся в спецификации и в отчёте:
`m = V·ρ` для дерева (ρ = 500 кг/м³) и `m = A·L·ρ` для стали (ρ = 7850 кг/м³).

Цены задаются в панели слева и считаются от этих же величин: дерево по объёму (₽/м³),
металл по массе (₽/кг), кровля по площади ската (₽/м²), метизы поштучно. Значения
по умолчанию — просто ориентир, подставляйте свои. Работа, фундамент и доставка не входят.

Ключевая особенность — **снеговой мешок у стены дома**: по СП 20, прил. Б, схема Б.8,
формула (Б.5) `μ = 1 + (m₁l₁ + m₂l₂)/(2h)` с ограничениями `μ ≤ 2h/S_g`, `μ ≤ 6` для навеса
и зоной `b = 2h ≤ 16 м`. Для навеса у дома обычно правит `2h/S_g`: нагрузка у стены равна
`2h` кПа и от снегового района не зависит — в мешок помещается слой толщиной h.

Второе — **ветровой отрыв**: отсос сверху плюс поддув снизу, `c ≈ 2,2`. Для лёгкой кровли
он определяет анкеры и массу фундамента.

## Как устроено

```
src/core/     чистое расчётное ядро, без DOM — гоняется в тестах
  version.js    версия программы — единственный источник
  sections.js   сортаменты; характеристики труб с учётом скруглений углов
  materials.js  R и коэффициенты условий работы для сосны и стали
  loads.js      снег, ветер, снеговой мешок, сочетания
  beam.js       МКЭ балки Тимошенко: произвольные опоры, консоли, сдвиг
  checks.js     проверки по СП 64 и СП 16
  common.js     общее для модулей расчёта: жёсткость, припуск стропила
  splices.js    стыки по длине: схема со стыком и накладка
  roof.js       стропила, обрешётка, прогон и обвязка как балки, нагрузки на опоры
  ties.js       узлы крепления: стропило к опоре, прогон к столбу
  posts.js      столбы, крест в ряду, диагонали в плоскости кровли
  bases.js      база столба, фундамент, пучение
  bom.js        спецификация, массы, смета
  analysis.js   сборка результата по цепочке — через него всё идёт наружу
  optimize.js   автоподбор сечений и шага
  search.js     подбор по минимальной стоимости: поэтапный перебор с отсевом
  share.js      упаковка модели в ссылку (только отличия от умолчаний)
  model.js      модель и levels() — высотные отметки, общие для расчёта, чертежа и сметы
src/ui/       интерфейс
  views.js      план, разрез, эпюры, узлы — результат расчёта → SVG
  controls.js   поля панели параметров: значения, пределы, справка
  warnings.js   предупреждения над сводкой (стыки, мороз)
  report.js     печатный отчёт
  theme.js, audio.js   тема оформления, фоновая музыка
  app.js        контроллер: состояние, перерисовка, панель, инспектор, перетаскивание
assets/audio/ фоновая музыка (1.mp3…8.mp3, загружаются через github.com)

```

Эпюры M и Q считаются точной статикой по найденным реакциям, поэтому не зависят от густоты
сетки. Сдвиговые деформации учтены элементом Тимошенко — для коротких деревянных балок это
+5…15 % к прогибу (тест сверяет это с формулой (50) СП 64).

### Вкладка «Узлы»

Четвёртый вид рядом с планом, разрезом и эпюрами — шесть узловых чертежей: стропило
на опоре, прогон на столбе и база, для наружного ряда и для стенового. Это то, что
распечатывают и везут на объект.

Всё собрано по числам расчёта, а не «примерно»: гвоздей на уголке ровно столько,
сколько посчитано, шаг между ними расчётный, катет шва и разнос анкеров подписаны
теми значениями, которые проверены. Не помещается крепёж — на чертеже так и написано:
«нужно 20, влезает 8». Клик по детали открывает её проверки справа.

### Крепление стропил от отрыва

Ветер поднимает лёгкую кровлю сильнее, чем её прижимает собственный вес, и
стропило висит на крепеже. Калькулятор считает этот узел: равнодействующую отрыва
и скатной составляющей, несущую способность крепежа на срез по табл. 20 СП 64 и
правила расстановки. Число крепежей подбирается, а проверяется то, помещается ли
оно в узле: если нет — нужен крепёж крупнее, а не «набить гуще».

Тип крепежа выбирается в блоке «Элементы»: уголок с ершёными гвоздями или
саморезами, либо сквозной болт. Уголок нужен затем, чтобы усилие пришло на крепёж
срезом: на выдёргивание гвозди и саморезы в несущих узлах не работают.

### Прогон на столбе

Вниз прогон держит само опирание, торец в торец. Узел нужен против ветрового
отрыва и горизонтальной силы — и считается в двух исполнениях: сварка по контуру
оголовка (швы по металлу шва и границе сплавления, с ограничением катета
`k_f ≤ 1,2·t_min` — на стенке 3 мм это 3,6 мм) или пластина-оголовок с болтами
(растяжение, срез, смятие стенки профиля либо древесины под шайбой). К деревянной
обвязке приварить нельзя, и расчёт об этом прямо пишет.

### Связи

Сечение наружного столба определяет не прочность, а гибкость, а гибкость — коэффициент μ.
Его не выбирают из списка: μ следует из того, что держит верх столба. Поперёк ряда это
стропила — распорки до стены, μ = 1, и сила, которой они держат ряд, проверяется в креплении
стропил, в обвязке и в стеновом ряду. Вдоль стены — либо ничего (столбы консоли, μ = 2),
либо крест в крайнем пролёте, либо диагонали в плоскости кровли (μ = 1). Связь считается на
ветер и условную поперечную силу столбов по формуле (18) СП 16: диагонали на растяжение,
гибкость и крепление; у креста — добавка в столбы пролёта, у диагоналей по кровле — в крайние
стропила ячейки. Подбор по цене сравнивает все три варианта.

### База столба

Место, где расчётная схема встречается с землёй. Пока вдоль стены связей нет, столб —
консоль, защемлённая внизу: база обязана воспринять момент от ветра и эксцентриситета
опирания. Считаются оба исполнения: плита с анкерами (смятие
бетона, изгиб плиты, растяжение анкеров от отрыва и момента, вырыв конуса, срез)
и забетонированный столб (вес блока против отрыва и наименьшая глубина заделки
10·h_сечения).

Разнос анкеров здесь решает всё: два анкера М12 на плите 200×200 принимают момент
1,7 кН·м впритык, а четыре на плите 250×250 — с тройным запасом.

## Ограничения

Не считаются: основание по грунту, анкерные уширения и другие конструктивные меры против пучения, кроме засыпки пазух непучинистым грунтом, подкосы до земли
(из связей считаются крест в ряду и диагонали в плоскости кровли), огнестойкость,
температурные воздействия, двускатные и арочные навесы. Опирание стропил
принято шарнирным (консервативно по моменту в пролёте). Внецентренное сжатие столбов
проверяется усилением момента по деформированной схеме — консервативнее табличного φ_e
прил. Д.3 СП 16.

Если при стыке встык кусок стропила, обрешётки, прогона или обвязки ложится меньше чем на
две опоры, это изменяемая схема: элемент не проверяется, в шапке и сводке стоит U = ∞.
Нагрузка с него передаётся дальше как с неразрезной балки — такой он станет, если стык
перенести или перекрыть накладкой.

Результат — инженерная оценка для частного строительства, а не проект, прошедший экспертизу.

Проектная спецификация: [`docs/SPEC.md`](docs/SPEC.md).
