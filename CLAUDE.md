# Правила работы с CanopyCraft

Калькулятор односкатного навеса у дома по СП 20, СП 64 и СП 16. Статическая страница:
исходники в `src/`, сборка (esbuild) собирает их в один `index.html`, который публикуется
как есть и открывается двойным кликом без сервера. Что считается и как устроено — `README.md`, расчётная часть —
`docs/SPEC.md`. Этот файл — правила: как менять проект, чтобы ничего не сломать.

## Команды

```bash
npm install       # один раз: инструменты сборки и проверки (esbuild, ESLint)
npm test          # тесты ядра и чертежей (node:test)
npm run lint      # ESLint: забытые импорты, необъявленные и неиспользуемые имена
npm run build     # собрать index.html, docs/app.artifact.html, help/help.css
npm run smoke     # смоук-тест интерфейса в Chrome; путь к Chrome — в переменной CHROME
npm run dev       # http://localhost:8080/dev.html — модульная версия для отладки
```

## Перед каждым коммитом

1. `npm test` и `npm run lint` — зелёные.
2. Правили `src/` или `dev.html` — `npm run build` и коммит **вместе** с собранными
   файлами. CI сравнивает сборку с исходниками и краснеет при расхождении.
3. Правили интерфейс, отчёт, ссылки или справку — `npm run smoke`.
4. Документация обновлена в том же коммите или PR (см. «Документация»).

## Архитектура — жёсткие правила

- **Библиотеки — можно, если дают заметный выигрыш.** Не «на всякий случай»: каждая —
  вес, обновления и то, что придётся понимать. Версия закрепляется точно (без `^`) и
  лежит в `package-lock.json`: от версии esbuild зависит собранный файл, а CI сверяет
  его побайтно. Библиотека для страницы (не инструмент) вшивается в сборку, а не
  грузится с CDN.
- **`index.html` — один файл, работает офлайн.** Открывается двойным кликом, без
  сервера и интернета. Всё, что нужно странице, собирается внутрь него.
- **`src/core/` — чистое расчётное ядро, без DOM и `window`.** Всё, что считает, живёт
  здесь и проверяется тестами. `src/ui/` только рисует и управляет.
- **Сгенерированные файлы руками не правятся:** `index.html`, `docs/app.artifact.html`,
  `help/help.css`. Источники — `dev.html`, `src/ui/*.css`, модули `src/`.
- **Сборка — esbuild** (`tools/build.mjs`): точка входа `src/ui/app.js`, модули
  собираются по импортам, стили и скрипт вклеиваются в `dev.html` → `index.html`.
  Новый модуль достаточно импортировать — регистрировать его в сборке не нужно.
- **`src/core/analysis.js` — фасад расчёта.** Элементы считаются в своих модулях
  (`roof`, `ties`, `posts`, `bases`, `splices`, смета — `bom`), а наружу — интерфейсу,
  подбору, тестам — всё идёт через `analysis.js`. Новая функция, нужная снаружи, —
  в его реэкспорт, чтобы импортёрам не знать, где что живёт.
- **Каждый модуль импортирует всё, чем пользуется; ядро не трогает браузер.** Ловит
  ESLint (`no-undef`): для `src/ui` разрешены имена браузера, для `src/core` — только
  общие для браузера и Node (таймеры, `TextEncoder`), `document` и `window` там — ошибка.
- **`src/ui/app.js` — контроллер:** состояние, перерисовка, события. Остальные модули
  интерфейса состояния не знают: чистые функции (`views`, `warnings`, `report` —
  результат на входе, SVG или HTML на выходе), описание полей (`controls`) или
  `init…(callback)` без действий при загрузке (`theme`, `audio`). Так модули не
  зависят от `app.js`, и циклов импорта нет.

## Единицы

Во всём ядре: **мм, Н, Н/мм (= кН/м), МПа, мм², мм⁴; давления — кПа; углы — градусы.**

- Исключение — формулы крепежа в `src/core/fasteners.js`: там кН и см, как в таблицах
  СП 64. Перевод — на границе функции, внутрь ядра кН и см не выходят.
- Единица пишется в комментарии к полю или в имени (`…Kpa`, `…Mm`), если из контекста
  не очевидна. В интерфейсе и отчёте у каждого числа есть подпись единицы.
- Масса — кг, сила — Н или кН. Не путать: масса фундамента однажды уже была подписана
  в килоньютонах (#39).

## Расчёты по нормам

- Нормы: СП 20.13330.2016 (нагрузки), СП 64.13330.2017 (дерево), СП 16.13330.2017
  (сталь), ГОСТ 30245-2003 и ГОСТ 24454-80 (сортамент), СП 22 и СП 24 (грунт, мороз).
  Другие редакции и нормы — только с явной записью в `docs/SPEC.md`.
- **Каждая формула и табличное значение — со ссылкой** на пункт, формулу или таблицу в
  комментарии рядом с кодом: `// формула (Б.5) СП 20`, `/** Табл. 3 СП 64 */`.
- **Спорная трактовка — в запас**, и она записывается словами: в комментарии и в
  `docs/SPEC.md`.
- **Нет данных — не выдумывать.** Значение, которое пользователь должен взять из карты
  или изысканий, по умолчанию «не задано» (0), а не «типичное по памяти»; расчёт тогда
  честно говорит, чего не хватает.
- Новое упрощение или то, что не считается, попадает в три места: «Ограничения» в
  `README.md`, раздел 9 `docs/SPEC.md`, `help/limits.html`.
- Проверка возвращает единый объект `{ name, value, limit, unit, U, formula, note }`,
  где `U = value / limit` (см. `src/core/checks.js`). Новая проверка — в том же виде,
  тогда она сама попадает в инспектор, карту U и отчёт.

## Тесты

- `node:test` и `node:assert/strict`, файлы `tests/*.test.js`.
- Имя теста — что проверяется, по-русски, со ссылкой на норму, если она есть:
  `'снеговой мешок: схема Б.8, формулы (Б.5) и (Б.6)'`.
- Новая формула — тест, который сверяет её с ручным счётом или точным решением.
  Сообщение в `assert` объясняет, что пошло не так, а не повторяет условие.
- Исправленная ошибка — тест, который падал бы без исправления.
- Тест нельзя удалять, отключать или ослаблять допуск, чтобы стало зелёным.
- Эталон — `tests/reference.test.js`: ручной счёт стропила и U варианта по умолчанию.
  Разошёлся эталон — сначала понять, почему изменился расчёт; число обновляется
  с комментарием, а в PR объясняется, что и почему сдвинулось.

## Чертежи (`src/ui/views.js`)

- Виды — чистые функции: на входе результат расчёта, на выходе строка SVG.
- **Геометрия только из расчёта:** отметки — из `levels()` (`src/core/model.js`),
  размеры, число крепежей, шаги и катеты — из результата `analyse()`. Своих констант
  «на глаз» в чертеже нет. Чертёж, нарисованный отдельно от расчёта, расходится с ним:
  так стропило однажды врезалось в опору.
- У каждого SVG есть `aria-label` с именем вида. В разметке нет `NaN` и `undefined`,
  ссылки `url(#…)` указывают на объявленные `defs` — это проверяет `tests/views.test.js`.
- Новый вид добавляется в список `VIEWS` в `tests/views.test.js`.
- **3D-вид** — то же правило: детали строит чистая `buildSolids(res)` (`src/ui/solids.js`)
  из модели, `levels()` и результата, а three.js (`src/ui/view3d.js`) только рисует.
  Стыковку деталей — стропило на прогоне и обвязке, столбы до них, обрешётка на
  стропилах — проверяет `tests/solids.test.js`. Цвета — из токенов темы, как у SVG.

## Стили и цвета

- **Палитра — только `src/ui/tokens.css`.** Из него собираются и калькулятор, и
  `help/help.css`.
- В `styles.css`, `help.css` и чертежах цвета только через `var(--…)`. Коэффициент
  использования красится через `uColor()` из `views.js`.
- Новый цвет — новый токен во всех трёх блоках `tokens.css` (светлая тема, тёмная по
  `prefers-color-scheme`, тёмная по `data-theme`) и в печатном блоке `@media print` в
  `styles.css`. Печатные блоки `styles.css` и `help.css` — единственное место вне
  `tokens.css`, где пишутся HEX-цвета: печать всегда светлая.
- Всё это проверяет `tests/palette.test.js`: цвет мимо токенов, токен, забытый в одной
  из тем или в печати, ссылка на необъявленный токен.
- Смоук проверяет контраст обеих тем и ширину телефона 390 px без прокрутки вбок и
  сохраняет скриншоты в `smoke-shots/` (в CI — артефакт прогона). Изменили вид —
  посмотрите скриншоты и печать отчёта.

## Интерфейс, ссылки и сохранения

- Поле панели описывается в списке `CONTROLS` в `src/ui/controls.js`. У каждого поля —
  статья справки (`help: 'файл.html#раздел'`, `helpTitle`) или пояснение `note`; без этого
  человек не поймёт, что вводить. Проверяет `tests/help.test.js`: и наличие, и что файл
  и раздел `id` существуют, и что каждая статья есть в `help/index.html`.
- Пояснение и ссылка на статью показываются в карточке у кнопки «?» (`src/ui/tip.js`),
  а не под полем: их читают пару раз, а место они заняли бы навсегда. Под полем — только
  «живая» строка `live`: состояние расчёта, которое меняется и которое нельзя прятать
  (например, «глубина промерзания не задана — пучение не проверяется»).
- Числа в статьях справки — посчитанные программой для навеса по умолчанию, а не
  «типичные». Изменился расчёт — пересчитайте примеры в статьях.
- Новая кнопка или сценарий — новый шаг в `tools/smoke.mjs`. Любое исключение или
  `console.error` в браузере — ошибка.
- **Старые ссылки на расчёт и сохранённые расчёты должны открываться всегда.** В ссылку
  кладутся только отличия от умолчаний (`src/core/share.js`), неизвестные ключи молча
  отбрасываются. Поэтому переименовали или убрали поле модели — перевод в `migrate()`
  в `share.js`, сообщение пользователю о том, что переведено, и шаг в смоуке со старой
  ссылкой.

## Документация

Меняется в том же PR, что и код:

- `README.md` — что считается, как открыть, ограничения;
- `docs/SPEC.md` — расчётная модель, формулы, архитектура;
- `help/*.html` — статьи для пользователя; новая статья — ссылка на неё с поля и из
  `help/index.html`.

## Тексты

- Язык интерфейса, справки, комментариев, тестов и коммитов — русский.
- Десятичная запятая в интерфейсе и отчёте (`2,5 кПа`), кавычки «ёлочки», тире — «—».
- Пишем простыми словами, что это значит для навеса, а не только номер формулы.

## Версия

- Версия — одна: `src/core/version.js`. Её же повторяют `package.json` и верхняя
  запись `CHANGELOG.md` — совпадение проверяет `tests/version.test.js`. Подвал и отчёт
  берут её из `version.js`, руками в разметку она не пишется.
- Поднимается в PR, который меняет поведение программы:
  - **минорная** (0.3.0 → 0.4.0) — изменились числа расчёта или появилось новое;
  - **патч** (0.3.0 → 0.3.1) — исправление, которое чисел не меняет;
  - документация, тесты, CI и рефакторинг без изменения поведения — версию не трогают.
- В `CHANGELOG.md` — запись того же PR: что изменилось для пользователя. Изменения,
  которые сдвигают числа расчёта, — отдельным блоком и с числами «было → стало»: по
  версии в отчёте человек поймёт, надо ли пересчитать свой вариант.
- Отчёт несёт версию и ссылку на расчёт — это его делает воспроизводимым. Ссылку и
  версию в отчёте проверяет смоук.

## Git

- Одна задача — одна ветка — один PR. После слияния ветка удаляется, следующая задача
  начинается с новой ветки от свежего `main`.
- Коммиты — `тип(область): что изменилось`, по-русски, в прошедшем или нейтральном
  времени. Типы: `feat`, `fix`, `docs`, `test`, `refactor`, `ci`, `chore`. Область —
  по желанию: `core`, `ui`, `search`, `help`.
  Примеры: `fix: трение о талый грунт — коэффициенты γc и γR,f по СП 24`,
  `feat(ui): схема связей вместо списков μ`.
- Описание PR — по шаблону `.github/pull_request_template.md`.
