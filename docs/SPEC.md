## 2. Нагрузки

### 2.1 Постоянные (собственный вес)

`g = g_кровля + g_обрешётка + g_стропила + g_прогоны` — кН/м² **по площади ската**.

Справочник кровель (кН/м²):

| Покрытие | g |
|---|---|
| Поликарбонат сотовый 6 мм | 0.013 |
| Поликарбонат сотовый 8 мм | 0.015 |
| Поликарбонат сотовый 10 мм | 0.017 |
| Поликарбонат монолитный 4 мм | 0.048 |
| Профлист С8–С21, 0.5 мм | 0.05 |
| Профлист НС35–Н60, 0.7 мм | 0.08 |
| Металлочерепица | 0.05 |
| Мягкая черепица по OSB-9 | 0.20 |

Собственный вес стропил, обрешётки, прогонов и столбов калькулятор считает сам из
подобранных сечений и включает в нагрузки:

```
дерево   m = b·h·L·n·ρ,   ρ = 500 кг/м³   (сухая сосна; свежераспиленная 700–800)
сталь    m = A·L·n·ρ,     ρ = 7850 кг/м³  (то же, что A[см²]·0,785 кг/м)
кровля   m = g·S/g₀,      g — вес покрытия по скату, S — площадь ската
погонный вес сечения      q = m·g₀ , кН/м — он и идёт в расчётную схему
```

Массы выводятся по группам (кровля, обрешётка, стропила, прогоны, столбы, метизы),
итогом по сосне в м³ и кг, по стали в пог. м и кг, и удельно — кг на м² навеса.
Отдельно показывается доля собственного веса в полной нагрузке: у стены она мала
(снеговой мешок перекрывает всё), в поле заметно больше.

γ_f: сталь 1.05, дерево 1.1, кровля заводская 1.2 (СП 20 табл. 7.1).
Для проверки на отрыв ветром — γ_f = 0.9.

### 2.2 Снег (СП 20 разд. 10)

**Нормативное** значение (п. 10.1): **S = c_e · c_t · μ · S_g**, кН/м² на горизонтальную проекцию.
**Расчётное**: **S_d = γ_f · S**, γ_f = 1,4 (п. 10.12).

⚠ Изменение № 2 перевернуло смысл таблицы 10.1: раньше она давала расчётные значения,
а нормативное получалось умножением на 0,7. Теперь наоборот — в таблице нормативные,
расчётное через γ_f = 1,4. Прогибы считаются на полное нормативное значение.

S_g по снеговым районам (табл. 10.1), кПа — **нормативные**:

| I | II | III | IV | V | VI | VII | VIII |
|---|----|-----|----|---|----|-----|------|
|0.5|1.0 |1.5  |2.0 |2.5|3.0 |3.5  |4.0   |

- `c_e` — снос ветром: 1.0 по умолчанию (для навеса у стены снос не работает — там наоборот намёт).
- `c_t` = 1.0 (холодное покрытие).
- `μ` для односкатного (прил. Б.1): α ≤ 30° → 1.0; 30° < α < 60° → (60−α)/30; α ≥ 60° → 0.

**Снеговой мешок у стены дома — критичный для навеса случай.**
СП 20.13330.2016, приложение Б, схема Б.8, профиль «в» рисунка Б.11 (навес).

```
(Б.5)  μ = 1 + (m₁·l′₁ + m₂·l′₂) / h          h > 8 м → принимается 8 м

«в»    при ширине нижнего покрытия a < 21 м:
       m₂ = 0,5·k₁·k₂·k₃, но не менее 0,1
       k₁ = √(a/21)
       k₂ = 1 − β/35     (при обратном уклоне k₂ = 1)
       k₃ = 1 − φ/30, но не менее 0,3
       m₁ = 0,4 при α ≤ 20°, иначе 0,3; сплошной парапет → m₁ = 0 (прим. 4)
       l′₂ не более утроенной ширины покрытия

«г»    при μ ≤ 2h/S₀:  b = 2h, не более 16 м
       при μ > 2h/S₀:  (Б.6) b = 2h·(μ − 1 + 2m₂)/(2h/S₀ − 1 + 2m₂),
                       но не более 5h и не более 16 м

«д»    потолок μ: 2h/S₀; для навеса 6; для покрытия здания 4 при l′ ≤ 48 м,
       6 при l′ > 72 м, между — интерполяция

«е»    μ₁ = 1 − 2m₂ — без парапетов при b ≥ l′₂ либо при μ ≤ 2h/S₀
       μ₁ = (l′₂ − 0,5·μ·b)/(l′₂ − 0,5·b) — в остальных случаях, не менее 0,2

прим. 3  при h < S₀/2 местную нагрузку у перепада не учитывают
```

**Эпюра** — линейный спад от μ у стены до μ₁ на длине b, дальше μ₁ до конца навеса.
Если `b > l′₂`, до μ₁ эпюра не доходит и на краю навеса остаётся часть мешка.

**Два варианта загружения.** Перечисление «а» требует считать нижнее покрытие дважды:
равномерно (схемы Б.1–Б.7) и с мешком (Б.8). Программа решает оба и берёт огибающую —
у стены правит мешок, в дальней части равномерный снег, потому что μ₁ бывает заметно
меньше единицы.

Для навеса у дома обычно правит ограничение **μ ≤ 2h/S₀**. Смысл геометрический:
в мешок помещается слой снега толщиной h при плотности 2 кН/м³, то есть нормативная
нагрузка у стены равна `2h` кПа и **от снегового района не зависит**.

### Крепление к дому

У стены стоит **второй ряд стальных столбов**, притянутых к газоблоку **сквозными
шпильками** с широкой шайбой-пластиной изнутри. Поверх них лежит **обвязочная доска**
(её часто называют мауэрлатом, но мауэрлат лежит на кладке — здесь это прогон по столбам),
по ней идут стропила.

Что это меняет в расчёте:

- стеновые столбы **раскреплены стеной** по всей высоте → μ = 1,0 вместо 2,0,
  сечение выходит вдвое легче наружных;
- обвязка считается как неразрезная балка на стеновых столбах;
- шпильки проверяются на **смятие газоблока под шайбой** (растяжение от горизонтального
  распора), **смятие газоблока в отверстии** и **срез шпильки**;
- расчётное сопротивление кладки из ячеистых блоков: B2,0 → 0,85; B2,5 → 1,0;
  B3,5 → 1,3 МПа (ориентир по СП 15.13330, уточнять по данным производителя).

**Важно про распор.** Сила тяжести горизонтального распора не создаёт: все опоры
вертикальные, ΣH = 0. Горизонталь даёт только ветер — горизонтальная проекция давления
по нормали к скату плюс напор на наружную кромку. Её по стропилам — распоркам от прогона
до обвязки — принимает стеновой ряд, вместе с тем, что держит верх наружного ряда
(см. «Связи»). Путь проверяется: крепление стропил у прогона и у стены, обвязка из своей
плоскости между стеновыми столбами, шпильки.

**Стропило** — наклонная балка. Приведение нагрузок:
```
q_гор  — на горизонтальную проекцию (снег)
q_ск   — на длину по скату (собственный вес)
q_⊥ = q_гор·cos²α + q_ск·cosα     (изгиб)
q_∥ = q_гор·cosα·sinα + q_ск·sinα (осевое сжатие вдоль стропила)
```
→ проверка как **сжато-изгибаемого** элемента.

Схема стропила: балка на 2–3 опорах (стена / промежуточный прогон / прогон по столбам)
**с консолью** на вылет `a`. Опора у стены — шарнир или защемление (выбор пользователя).

**Прогон по столбам** — неразрезная балка на N опорах (столбы) с сосредоточенными силами
от стропил, плюс консоли по краям, если навес выступает за крайние столбы.

**Обрешётка** — неразрезная балка, пролёт = шаг стропил.

**Столб** — сжато-изгибаемый: N от вертикальных нагрузок, M от ветра и от эксцентриситета
опирания прогона.

### Универсальный решатель

Вместо табличных формул — **1D-МКЭ балки Тимошенко** (2 узла × 2 DOF: v, θ; сдвиг учитывается
через GA/κ, κ = 5/6 для прямоугольника). Это даёт:

- любое число и положение опор (пользователь двигает столбы — схема пересобирается),
- любые консоли,
- эпюры M(x), Q(x), v(x) в 100+ точках,
- корректный прогиб коротких деревянных балок (для сосны сдвиг даёт +5…15 % прогиба;
  эквивалент формулы (50) СП 64: f = f₀·[1 + c·(h/l)²]).

Опоры: шарнирная / защемление / упругая (жёсткость k). Нагрузки: равномерная, трапеция
(снеговой мешок), сосредоточенная сила, момент.

Коэффициенты условий работы:

- `m_т` = 1.0, `m_дл` = 1.0 для сочетаний со снегом (табличные R уже это учитывают);

Проверки:

1. **Изгиб**: `σ = M / W_расч ≤ R_и · m_в · m_дл`, W = b·h²/6 (минус ослабления врубками).
2. **Сжатие с изгибом** (п. 7.17): `N/(A_расч·R_с) + M_д/(W_расч·R_и) ≤ 1`,
   где `M_д = M / ξ`, `ξ = 1 − λ²·N/(3000·A·R_с)` — учёт продольного изгиба.
3. **Скалывание**: `τ = 1.5·Q/(b·h) ≤ R_ск · m_в`.
4. **Устойчивость плоской формы изгиба** (п. 7.4.2): `σ ≤ φ_м · R_и`,

   ⚠ На консоли сжата **нижняя** кромка, где обрешётки нет → l_р = вылет консоли.

5. **Смятие на опоре**: `σ_см = R_оп/(b·l_оп) ≤ R_см,90`. Определяет минимальную площадку

6. **Прогиб** (табл. 19, от нормативных нагрузок):
   - стропила, прогоны — `l/200`
   - обрешётка, настил — `l/150`

## 5. Проверки — профильная труба (СП 16.13330.2017)

Стали: С245 R_y = 240 МПа | С255 R_y = 240 (t≤20) | С345 R_y = 315 МПа. R_un = 370/370/470.
R_s = 0.58·R_y. E = 2.06·10⁵ МПа, G = 0.79·10⁵ МПа. γ_c = 1.0 (дефолт), γ_n = 1.0.

Геометрические характеристики — **из таблиц ГОСТ 30245-2003** (JSON-сортамент), а не по
формуле «разность прямоугольников» (та завышает A и I на 3–6 % из-за скруглений — в опасную сторону).

Проверки:

1. **Изгиб** (ф. 41): `M / W_n,min ≤ R_y · γ_c`.
   Опция «учёт пластики» (ф. 42): `M/(c₁·W) ≤ R_y·γ_c`, c₁ ≈ 1.10 для прямоугольных труб — по умолчанию **выключено**.
2. **Косой изгиб** (наклонное стропило из трубы): `M_x/(c_x·W_x) + M_y/(c_y·W_y) ≤ R_y·γ_c`.
3. **Срез** (ф. 44): `τ = Q·S/(I·2t) ≤ R_s·γ_c`.
4. **Прогиб** (СП 20 прил. Д): элементы покрытий `l/200`; эстетико-психологические
   по табл. Д.1 с интерполяцией: l = 1 м → 1/120; 3 м → 1/150; 6 м → 1/200; 12 м → 1/250.
5. **Столб — устойчивость при центральном сжатии** (п. 7.1.3):
   ```
   λ = l_ef / i,   l_ef = μ·l,   λ̄ = λ·√(R_y/E)
   λ̄ ≤ 0.4      →  φ = 1
   0.4 < λ̄ ≤ 3.8 →  δ = 9.87·(1 − α + β·λ̄) + λ̄²
                     φ = 0.5·(δ − √(δ² − 39.48·λ̄²)) / λ̄²
   λ̄ > 3.8      →  φ = 332 / (λ̄²·(51 − λ̄))
   Гнутосварные замкнутые профили — тип кривой «b»: α = 0.04, β = 0.09
   Проверка: N / (φ·A·R_y·γ_c) ≤ 1
   ```
   Коэффициент расчётной длины μ — **отдельно в двух плоскостях**: поперёк ряда
   (x — к дому и от дома; в этой же плоскости эксцентриситет опирания) и вдоль
   ряда (y — вдоль стены). μ **не задаётся**, а следует из схемы связей
   (`model.bracing`, `postMu`) — см. «Связи» ниже. Устойчивость проверяется
   в каждой плоскости своей длиной; гибкость и местная устойчивость стенки — по
   той плоскости, которая правит общей устойчивостью (там наибольшая λ и
   наименьший φ). Сжатие с изгибом у наружного столба — в двух плоскостях:
   `N/(φ_min·A·R_y) + M_x·η_x/(W_x·R_y) + M_y·η_y/(W_y·R_y) ≤ 1`, моменты
   складываются, φ по худшей плоскости — в запас.
   ⚠ Вдоль стены без связей μ_y = 2.0, и именно эта проверка, а не прочность,
   определяет сечение столба. Жёсткий узел (подкос столб–прогон) смещаемость
   рамы не снимает: право на μ = 1.0 даёт только связь, не дающая верху уехать вбок.
6. **Столб — внецентренное сжатие** (п. 9.2.2, ф. 109):
   `N/(φ_e·A·R_y·γ_c) ≤ 1`, φ_e по прил. Д.3 от λ̄ и m_ef = η·m, m = (M/N)·A/W.
   Fallback (консервативно, с предупреждением): `N/(φ·A) + M/W ≤ R_y·γ_c`.
7. **Предельная гибкость**: колонны `λ_u = 180 − 60·α`, α = N/(φ·A·R_y·γ_c) ≥ 0.5;
   второстепенные элементы λ_u = 200.
8. **Местная устойчивость стенки** (табл. 9): `b_ef/t ≤ (1.2 + 0.35·λ̄)·√(E/R_y) ≤ 1.9·√(E/R_y)`.

## 6. Узлы, отрыв, фундамент

### Крепление стропила к опоре (СП 64, разд. 8 и табл. 20)

Считается. Ветер поднимает лёгкую кровлю: при покрытии из профлиста собственный
вес отрыв не перекрывает, и стропило висит на крепеже.

**Схема узла.** Стропило прижато к опоре перфорированным уголком с двух сторон
либо сквозным болтом. Уголок здесь не для жёсткости: он переводит отрыв в **срез**
крепежа — на выдёргивание гвозди и саморезы в несущих узлах работать не должны.

**Усилие.** Равнодействующая отрыва и скатной составляющей в том же сочетании
(0,9·постоянная − ветровой отсос; снега в нём нет). Скатная составляющая доходит
только до нижней опоры — до наружного прогона.

**Несущая способность одного крепежа на один шов**, кН при размерах в см:

```
смятие древесины   T_см = 0,35·c·d     c — глубина защемления
изгиб гвоздя       T_и  = 2,5·d²       при стальной накладке a = 0
изгиб винта        T_и  = 1,6·d²
изгиб болта        T_и  = 1,8·d²
T = min(T_см, T_и)·m_в
```

Слагаемое 0,01·a² (0,02·a² для стальных нагелей) не учитывается: накладка
стальная, толщина крайнего деревянного элемента принята нулевой — это в запас.

**Число крепежей подбирается** с целевым запасом 0,85, минимум два на узел.
Проверяется не оно, а то, **помещается ли** это число в узле по правилам
расстановки (S1 = 15d вдоль волокон и 4d поперёк для гвоздей и саморезов,
7d и 3,5d для стальных нагелей; полка уголка принята 90 мм). Если не помещается —
нужен крепёж крупнее, а не «набить гуще». Для стальной опоры дополнительно
проверяются срез самосверлящего винта и смятие стенки профиля (R_bp = 1,35·R_un).

### Крепление прогона к столбу (СП 16, разд. 14)

Считается. Вертикальную нагрузку вниз держит само опирание, торец в торец, —
узел для неё не нужен. Узел держит то, что пытается снять прогон с оголовка:
ветровой отрыв, горизонтальную силу и, у жёсткого узла, момент от
эксцентриситета опирания.

**Сварной узел** — угловые швы по контуру оголовка, только для стального прогона:

```
A_ш = β·k_f·l_ш,   l_ш = 2(b + h) − 4·10 мм       непровар по 10 мм на каждый из четырёх швов
W_ш = β·k_f·(b·h + h²/3)                          момент сопротивления линии шва
τ   = √( (N_отр/A_ш + M/W_ш)² + (H/A_ш)² )
по металлу шва          β_f = 0,7,  τ ≤ R_wf = 200 МПа (электроды Э46)
по границе сплавления   β_z = 1,0,  τ ≤ R_wz = 0,45·R_un
```

Плюс конструктивное ограничение, которое обычно и оказывается решающим:
`k_f,min (табл. 38) ≤ k_f ≤ 1,2·t_min`. На трубе со стенкой 3 мм это значит
катет не больше 3,6 мм — шов «пожирнее» здесь не помогает, а вредит.

**Болтовой узел** — пластина-оголовок, приваренная на торец столба, прогон на
болтах. Узел в один ряд принят шарнирным: момент от эксцентриситета
воспринимается смятием площадки опирания, болты держат отрыв и сдвиг.

- растяжение болта: `N/n ≤ R_bt·A_bn` (R_bt по табл. Д.5, A_bn — площадь нетто);
- срез болта: `Q/n ≤ R_bs·A`;
- стальной прогон — смятие стенки профиля болтом;
- деревянная обвязка — смятие поперёк волокон под шайбой (σ ≤ R_см90) и работа
  болта как нагеля от горизонтальной силы (табл. 20 СП 64).

К деревянной обвязке приварить нельзя: если выбрана сварка, расчёт считает
болтовой узел и пишет об этом в инспекторе.

### Крепление стеновых столбов к газоблоку

- усилия в сквозных шпильках по эпюре столба как балки на опорах в отметках шпилек;
- смятие газоблока под шайбой-пластиной и в отверстии: σ ≤ 1,2·R_кладки;
- срез шпильки: τ = Q/A_нетто ≤ R_bs.

### Связи: что держит верх наружного ряда

μ не выбирается из списка, а следует из схемы. Список давал поставить 1,0 без
единой связи, и столб проходил, хотя верх ничем не удержан; силы при этом
считались по одной схеме (всё горизонтальное — к стене), а устойчивость по другой.

| Ряд, плоскость | Что держит верх | μ | Что проверяется |
|---|---|---|---|
| стеновой, обе | стена, шпильки | 1,0 | шпильки |
| наружный, поперёк (x) | стропила — распорки до стены | 1,0 | крепление стропил у прогона и у стены, обвязка из плоскости, стеновой ряд |
| наружный, вдоль (y), `bracing.along = 'none'` | ничего — консоль | 2,0 | столб на изгиб от ветра вдоль стены, база на момент |
| наружный, вдоль (y), `'cross'` | крест в крайнем пролёте (`bays`: 1 или 2) | 1,0 | диагонали, шов, столбы пролёта и их базы |
| наружный, вдоль (y), `'roof'` | диагонали в плоскости кровли в крайней ячейке (`roofBays`: 1–3 шага стропил) | 1,0 | диагонали, крепление концов, крайние стропила, шпильки |

Раскреплённому верху даётся 1,0, а не 0,7: для 0,7 база должна быть рассчитана на
защемление, а при связи вверху её так не считают.

**Сила, которую держит связь** — ветер плюс условная поперечная сила каждого
удерживаемого столба (СП 16, формула (18); правило считать на неё связи,
уменьшающие расчётную длину, — СНиП II-23-81* п. 5.8*):
```
Q_fic = 7,15·10⁻⁶·(2330 − E/R_y)·N/φ        φ — в раскрепляемой плоскости
```
N — сжатие столба от прогона и собственного веса, **без** вертикальной силы самого креста
V = F·h_d/s: она зависит от Q_fic, и этот круг не замыкается. Упрощение не в запас, но
малое — у варианта по умолчанию с крестом около 1,5 % силы на крест (эталон в
`tests/reference.test.js`).
- поперёк: `holdX = Σ(H_wind,i + Q_fic,x,i)` по наружному ряду уходит по стропилам
  к стене. На одно стропило `holdX/n` у прогона и `(распор кровли + holdX)/n` у стены —
  складывается со скатной составляющей по модулю. Обвязка у стены — неразрезная балка на
  стеновых столбах из своей плоскости (`I_y`, `W_y`), нагрузка по грузовым ширинам стропил;
  стена как опора не учитывается.
- вдоль: доля ветра на торец кровли, приходящаяся на наружную опору стропила,
  `alongOuter = alongWall·min(1, (L + a)/(2L))`. Без связей она делится между
  консолями ряда. С крестом `F = (alongOuter + ΣQ_fic,y)/bays`. Шпильки у стены
  по-прежнему считаются на весь `alongWall` — если кровля работает диском, вся сила
  уйдёт к дому.

**Крест.** Диагонали — квадратная труба, крепятся на 150 мм от базы и от оголовка:
`h_d = H − 300`, `l = √(s² + h_d²)`. Работает растянутая диагональ:
```
T = F·l/s          растяжение, N ≤ A·R_y·γ_c
λ = l/i_min ≤ 400  табл. 33 СП 16
V = F·h_d/s        столбам пролёта в сжатие; в отрыв — только ветровая часть
                   V_up = (alongOuter/bays)·h_d/s: Q_fic — от сжатия под снегом
шов по контуру торца: τ = T/(β·k_f·l_ш),  k_f,min по табл. 38 ≤ k_f ≤ 1,2·t_min
```
К стенке 2 мм не приварить ничего (k_f,min = 3 > 1,2·2): подбор при кресте такие
столбы не предлагает, а подбор по цене считает оба варианта наружного ряда.

**Диагонали в плоскости кровли** (`analyseRoofBrace`). Горизонтальная ферма в крайней
ячейке: пояса — наружный прогон и обвязка у стены, стойки — стропила 1 и k+1, раскосы — две
диагонали, работающие на растяжение по очереди. Ширина ячейки w = x[k] − x[0], длина —
скат между опорами L_ск:
```
T = F·l/w,   l = √(w² + L_ск²)        растяжение, гибкость ≤ 400
N = F·L_ск/w                          стропилам-стойкам: сжатие с изгибом с N_стропила + N
крепление: к стали — шов по контуру торца (k_f,min по табл. 38 ≤ k_f ≤ 1,2·t_min);
к дереву — болты М12 как нагели (табл. 20 СП 64), n = ⌈T/(0,85·T₁)⌉ ≤ 4, и срез болта
```
Столбы вертикали от связи не получают. Сила уходит по обвязке в шпильки: к ветру вдоль стены
(он там уже весь) добавляется ΣQ_fic,y наружного ряда.

**Старые ссылки** с μ переводятся: μ ≤ 1 вдоль ряда → крест; μ поперёк больше не
выбирается. Что переведено, говорится в подсказке (`decodeNotes`, `upgradeModel`).

### База столба

Считается. Это место, где расчётная схема встречается с землёй: расчёт столба
с μ = 2 хоть в одной плоскости предполагает защемление внизу, значит, база
обязана воспринять момент от горизонтальной силы. Два анкера с малым разносом
такой момент не держат.

Момент в базе: вдоль ряда без связей — консоль `H_y·H`; поперёк ряда верх удержан
стропилами, низ принимается шарниром, но плита с анкерами часть момента заберёт —
базе даётся половина момента от эксцентриситета `M_ecc/2` (защемлённый низ при
удержанном верхе). Моменты двух плоскостей складываются по модулю. Горизонтальная
сила — ветер вдоль стены на консоль плюс, у столба с крестом, сила креста.
Вертикальная сила — отрывающая, с добавкой от креста у столбов его пролёта.
Строго это разные сочетания, но вместе они дают верхнюю оценку растяжения
в анкере — в запас.

**Плита с анкерами:**

```
смятие бетона      σ = N/A + M/W ≤ R_b            A = a², W = a³/6
изгиб плиты        σ = 6·M_c/t² ≤ R_y             M_c = σ_б·c²/2, c — вылет за грань столба
анкер на растяжение N_a = N_отр/n + M/(s·n/2) ≤ R_bt·A_bn      s — разнос анкеров
вырыв конуса       N_a ≤ R_bt,бетона·π·h_ef²      конус под 45°
срез анкеров       Q/n ≤ R_bs·A
```

**Забетонированный столб:**

- вес блока против отрыва: `N_отр ≤ 0,9·m·g`, блок считается по заданной стороне
  подошвы и глубине заделки — это единственное, что держит навес от вырыва вверх;
- глубина заделки при схеме с защемлением: `h ≥ 10·h_сечения`. Это конструктивное
  правило, а не расчёт по грунту: ниже этого о защемлении говорить нельзя.

Расчёт основания по грунту (осадка, несущая способность) по-прежнему не делается.

### Отрыв и фундамент (оценочный блок)

- **Отрыв кровли**: `w_отр · шаг обрешётки · шаг саморезов ≤ несущая способность самореза` →
  выдаём требуемый шаг крепления кровли.
- **Фундамент**: требуемая масса против отрыва наружного столба и сторона
  бетонного куба, дающего эту массу. Основание по грунту не считается.

### Блок фундамента

Вес бетона — единственное, что держит лёгкий навес от вырыва вверх, поэтому блок под столбом
задаётся размерами (`postBase.footing` — сторона, `postBase.depth` — глубина) и проверяется
`anchorMass` у **обеих** баз: и у забетонированного столба, и у базы на плите. Раньше проверка
была только у первой, а у второй требуемая масса лишь выводилась в инспекторе и в U не входила.

У забетонированного столба блок не может быть мельче заделки: в расчёт идёт
`max(depth, base.embed)`. Расчёт возвращает `needDepth` и `needSide` — какой глубины хватит при
нынешней стороне и наоборот; по ним работают кнопки «подобрать» у ползунков и автоподбор,
который растит блок вглубь, а упёршись в предел — вширь. Подбор целится в U ≤ 0,9, как и
сечения, а `needDepth`/`needSide` — это ровно единица.

### Мороз

`site.frostDepth` — нормативная глубина промерзания **для суглинков** по карте, мм; `site.soil` —
грунт на площадке. Карты дают глубину для суглинков, поэтому ввод такой, а на свой грунт
пересчитывается отношением d₀ (`frostDepth` в `core/fasteners.js`): по СП 22 п. 5.5.3
d_fn = d₀·√M_t, и √M_t у одного места общий, так что пересчёт точный. Расчётная глубина
d_f = k_h·d_fn с k_h = 1,1 — навес не отапливается.

Для пучинистых грунтов в карточку «База столба» добавляется проверка «Подошва ниже
промерзания»; для непучинистых не применяется (табл. 5.3). Подбор блока и кнопка «подобрать
глубину» берут максимум из требований по весу и по морозу.

По умолчанию глубина не задана (0): проверенного числа для места по умолчанию нет, и
подставлять его наугад хуже, чем предупредить. Над сводкой предупреждение «не задано».

**Касательные силы пучения** (СП 22.13330.2016 с Изм. 5, п. 6.8.6, ф. (6.35)) —
проверяются для пучинистого грунта при заданной глубине промерзания:
```
τ_fh·A_fh − F ≤ (γ_c/γ_n)·F_rf         γ_c = 1,0, γ_n = 1,1
в коде: τ_fh·A_fh ≤ F + F_rf/1,1        U = тянет / держит
```
- τ_fh — табл. 6.12: строка по состоянию грунта (`site.soilState`: I_L > 0,5 или S_r > 0,95
  — 110/90/70 кПа; 0,25 < I_L ≤ 0,5 — 90/70/55; I_L ≤ 0,25 — 70/55/40), столбец по глубине
  промерзания-оттаивания до 1,5 / 2,5 / 3 м и более с интерполяцией. Глубина берётся
  нормативная d_fn: она меньше расчётной, а τ с глубиной падает — в запас. Обратная засыпка —
  первая строка (прим. 3).
- множители: поверхность блока (`postBase.surface`, прим. 4) — опалубка 1,0; залит в яму,
  неровности до 5 мм — 1,2, до 20 мм — 1,5 (верх диапазонов); геотехническая категория 1
  (`site.geoCat1`, прим. 5) — 0,9.
- A_fh = 4·сторона·min(d_f, глубина блока) — верх блока на уровне земли.
- F — одна постоянная нагрузка при γ_f = 0,9 на самый лёгкий столб ряда (`Nperm`: реакция
  прогона от 0,9·постоянной плюс 0,9·вес ствола) и 0,9·вес блока.
- F_rf = ΣR_f·A_f (ф. (6.38)) — трение о талый грунт ниже промерзания, как у набивной сваи
  на выдёргивание (СП 24.13330.2021, п. 7.2.13, ф. (7.16)): R_f = γc·γ_R,f·f_i.
  f_i — табл. 7.3 (`skinFriction`), слои не толще 2 м (прим. 2); γ_R,f — табл. 7.6, строка 3а
  «буровые, насухо» (`FRICTION_GAMMA_RF`): 0,6 для «суглинков и глин» (худшее), 0,7 для
  супесей; γc = 0,6 при заглублении меньше 4 м, 0,8 — от 4 м (`upliftGammaC`). В запас: I_L —
  верхняя граница состояния грунта (1,0 / 0,5 / 0,3), глубина — ближайшая меньшая строка
  таблицы, надбавки прим. 3 и 4 к табл. 7.3 не берутся. γc,g из п. 7.1.11 не применяется:
  это коэффициент надёжности свайного фундамента, в (6.35) уже есть γ_n.
  Анкерная работа уширения на выдёргивание п. 7.2.13 не учитывается — в (7.16) нет члена
  с площадью уширения, — и калькулятор её не считает.

Мера против пучения (`postBase.antiHeave`): `'replace'` — пазухи засыпаны непучинистым
грунтом (п. 6.8.12): проверка не применяется, над сводкой предупреждение, что так и надо
сделать. Уширение, скользящий слой и утеплённый фундамент не считаются.

Размером блока и исполнением базы пучение не лечится, поэтому подбор базы и подбор по цене
смотрят на `Usized` — всё, кроме этой проверки; в сводке и в U базы она остаётся.

### Что по узлам ещё не считается

Расчёт основания по грунту (несущая способность и осадка). Сварные швы считаются в узле
«прогон — столб», в стальных накладках стыков и в креплении диагоналей креста; крепление
обрешётки конструируется вручную.

**Стыки по длине.** `splicePlan` (`core/model.js`) раскладывает стыки от левого конца через
длину хлыста и проверяет опирание каждого куска; `spliceReport` (`core/splices.js`) прогоняет
через неё стропило, обрешётку, обе балки и столбы, а спецификация выдаёт число хлыстов и
стыков вместо прежнего прочерка. Кусок, попавший меньше чем на две опоры, помечается как
геометрически изменяемая схема.

Стык входит и в расчётную схему. `opts.spliceJoint`: `butt` — встык, момент через стык не
передаётся; `plate` — накладка восстанавливает сечение, балка остаётся неразрезной. По
умолчанию `butt`, худший случай — как μ = 2 у столбов: программа не вправе считать, что
накладка есть. `spliceScheme` (и обёртка `spliceHinges`) отдаёт координаты шарниров, они идут в `solveBeam` через
`hinges` и применяются к стропилу, обрешётке, прогону и обвязке.

Стык встык раскладывается только по опорам (`spliceAtSupports`): он не передаёт ни момента,
ни поперечной силы, поэтому обязан лежать на опоре — иначе куски не связаны ничем. Берётся
самая дальняя опора в пределах хлыста, как и режут на практике. Если опоры в пределах хлыста
нет, собрать нельзя, и это отдельная ошибка (`impossible`), а не пониженный запас.

**Изменяемая схема.** Кусок между стыками встык меньше чем на двух опорах — механизм: он
поворачивается вокруг единственной опоры. Решатель такую систему всё равно «решает» —
матрица вырождена, прогиб выходит порядка 10¹² мм, U ≈ 4·10¹¹, а нагрузка с болтающегося
куска теряется из реакций. Поэтому `spliceScheme` (`core/splices.js`) для такого элемента
шарниров не отдаёт, и элемент решается неразрезным — таким он станет со стыком на
накладке. По этим реакциям нагрузка идёт дальше: на прогоны, столбы, узлы и фундамент.
Сам элемент не проверяется — вместо проверок у него одна `mechanismCheck` (`core/checks.js`):
«Изменяемая схема», value — число таких кусков, предел 0, U = ∞. Бесконечность явная, а не
NaN от испорченных данных: по ней шапка пишет «U = ∞ · стропила: изменяемая схема», а не
«расчёт не сошёлся», карточки и отчёт показывают «∞», эпюры вместо графиков — надпись.
Так обрабатываются стропило, обрешётка, прогон и обвязка.

Стропило влезает в хлыст или нет — решается по длине с припуском на торцовку 100 мм
(`RAFTER_TRIM`), той же, что в спецификации и в предупреждении о стыке. Раньше расчётная
схема брала длину по скату без припуска, и при длине 5900–6000 мм предупреждение говорило
«изменяемая схема», а проверки стропила проходили.

В решателе шарнир сделан статической конденсацией поворота у правого от стыка элемента:
узловой поворот остаётся за левым элементом, правый примыкает шарнирно. Это точно, а не
приближённо, и не ломает ленточную структуру матрицы. Исключённый поворот восстанавливается
для интерполяции прогиба — иначе участок справа от стыка считался бы по чужому повороту.
Проверено на двухпролётной балке: со стыком над средней опорой получаются две простые
балки (M = qL²/8 в пролёте, ноль в стыке, f = 5qL⁴/384EI по обе стороны).

**Узел стыка.** При `plate` накладка считается как настоящий узел — `analyseSpliceJoints`
берёт M и Q в сечении стыка из эпюры ULS и подбирает исполнение снизу, с целевым запасом 0,85.

Сосна: две боковые накладки на нагелях, симметричное двухсрезное соединение (`dowelDouble`,
табл. 20 СП 64 — наименьшее из смятия среднего элемента, смятия крайних и изгиба нагеля).
Нагели ставятся в два ряда по высоте с шагами S1 = 7d, S2 = 3,5d, S3 = 3d; если сечение
низкое и второй ряд не помещается, остаётся один. Усилие на крайний нагель — от момента
группы относительно её центра тяжести плюс доля поперечной силы; момент переносится по
модулю, потому что у двух групп по обе стороны стыка эксцентриситет противоположный и одной
из них поперечная сила момент добавляет. Подбор идёт от наименьшего числа нагелей, а не от
наименьшего диаметра: сверлить двадцать отверстий вместо восьми никто не станет.

Сталь: две накладки по боковым стенкам на угловых швах по контуру (`weldLine`), каждая берёт
половину момента и половину поперечной силы; накладка не тоньше стенки профиля, катет шва —
наименьший допустимый по табл. 38 и не больше 1,2·t.

Накладка проверяется и сама, на изгиб по половине момента. Накладки и нагели входят в
спецификацию. Стык обрешётки не считается узлом никогда: её стыкуют внахлёст на стропиле,
поэтому для неё стык всегда шарнир на опоре.

**На чертежах.** Вкладка «Узлы» получает третий ряд — детали 4.x по одной на стыкуемую
балку: вид сбоку с двумя кусками, накладкой, нагелями в расчётной сетке или штриховкой шва,
размерами накладки и шага S1. Стык встык рисуется торцами над опорой, без U — считать там
нечего. План отмечает стык поперечной риской, эпюры — линией «M = 0». Разрез стык не
показывает: он идёт вдоль балок, то есть перпендикулярно плоскости разреза, поэтому под
чертежом стоит строка с отметками стыков и тем, на чём они держатся.

**Высота сцены.** На экране шире 1000 px область чертежа — по высоте окна (поле забирает
всё, что остаётся после легенды и подсказки) и прилипает к верху, пока прокручиваются
длинные панели по бокам. На узком экране панели идут друг под другом, и поле — не выше
72 % окна.

**Что где лежит.** Слева — то, что крутят непрерывно: «Геометрия» и «Элементы»
(включая покрытие), а под ними «Крепление к дому». Справа, под инспектором
выбранного элемента, — то, что задают один раз: «Площадка» (снеговой и ветровой
районы, тип местности, параметры снегового мешка — это свойства участка, а не
конструкции), «Материалы» и «Цены»: цены оказываются рядом со стоимостью, к
которой относятся.

Каждый блок сворачивается. По умолчанию открыты «Геометрия» и «Элементы»,
остальные свёрнуты; состояние сохраняется в localStorage и переживает
перезагрузку.

**Вкладка «Узлы».** Четвёртый вид рядом с планом, разрезом и эпюрами: шесть узловых
деталей — стропило на опоре, прогон на столбе и база, для наружного ряда и для стенового.
Всё рисуется по числам расчёта: крепежей ровно столько, сколько посчитано, шаги между
ними расчётные, катет шва и разнос анкеров подписаны проверенными значениями. Если крепёж
в узел не помещается, на чертеже так и написано: «нужно N, влезает M». Клик по детали
открывает её проверки в инспекторе.

**Тема.** Кнопка в шапке переключает три положения: «как в системе» (по умолчанию),
светлая, тёмная. Палитра целиком на CSS-переменных, так что переключение — это один
атрибут `data-theme` на `<html>`; при «как в системе» атрибута нет и решает
`prefers-color-scheme`. Выбор хранится в localStorage и применяется маленьким
скриптом в `<head>` до первой отрисовки, иначе при тёмной теме мелькает светлый фон.
Печать всегда светлая, какая бы тема ни стояла на экране.

**Справка.** Отдельные страницы в `help/` — статьи о том, что стоит за полями: коэффициент
использования U, подбор по цене, раскрепление столбов (μ), снеговой мешок, границы
применимости. Ведут туда кнопка «Справка» в шапке и кружки `?` у полей, к которым статья
относится (поле `help` в описании контрола), у легенды под чертежом (U) и в заголовке
таблицы подбора (цена). Страницы статические, палитру берут из общих токенов через
собираемый `help/help.css`.

### Карта нагрузок

Каждый элемент окрашивается по **коэффициенту использования** U = max(всех проверок):

| U | цвет | смысл |
|---|---|---|
| < 0.5 | синий | большой запас, можно уменьшить сечение |
| 0.5–0.85 | зелёный | норма |
| 0.85–1.0 | жёлтый | на пределе |
| > 1.0 | красный | **не проходит** |

Плюс:
- **тепловая заливка поля кровли** по прогибу — сразу видно, где провисает;
- **штриховка зоны снегового мешка** у стены — объясняет, почему там красное;
- наведение на элемент → тултип с числами (M, Q, f, U по каждой проверке);
- клик → правая панель со всеми проверками и формулами.

### Прямые манипуляции

| Действие | Как |
|---|---|
| Двигать столб | перетаскивание вдоль стены, снап 50 мм, показ пролёта |
| Двигать стропило | перетаскивание, показ шага слева/справа |
| Добавить/убрать стропило | двойной клик / Del |
| «Распределить равномерно» | кнопка |
| Менять вылет, свес, уклон, высоту | перетаскивание размерной линии или ввод числа |
| Отменить / вернуть | Ctrl+Z / Ctrl+Y (и Ctrl+Shift+Z), кнопки ↶ ↷ в шапке |

**Отменить и вернуть.** История — снимки модели после каждой перерисовки (`src/ui/history.js`),
до 100 шагов, только в пределах открытой страницы. Изменения чаще чем раз в 0,4 с сливаются в
один шаг: протянутый ползунок или перетаскивание столба отменяются целиком, а не по кадру.
Отменяются и «Сбросить», и подбор, и загрузка другой ссылки. Клавиши — по физической клавише,
поэтому работают и в русской раскладке. В поле ввода Ctrl+Z, Backspace и Delete принадлежат
полю: отменяют и стирают набранный текст, а не расчёт.

Пересчёт — на каждое изменение (расчёт занимает миллисекунды, МКЭ на 100 узлов).

### Автоподбор

Кнопка «Подобрать» по каждому элементу и «Подобрать всё»:
- перебор сортамента снизу вверх до U ≤ 1.0 с целевым запасом 0.85;
- отдельно — «подобрать шаг» при фиксированном сечении (что чаще нужно на практике:
  доска 50×200 уже куплена — на каком шаге её класть);
- вывод 2–3 альтернатив с ценой в м³ / кг металла;
- узлы подбираются последними, когда сечения уже известны: каталоги упорядочены
  от простого к сложному (гвозди → саморезы → болты; тонкий шов → толстый →
  пластина с болтами), и берётся первое проходящее исполнение. Порог для узлов —
  1,0, а не общий целевой запас: внутри узла запас уже заложен (число крепежей
  считается с коэффициентом 0,85), а вместимость узла и катет шва дискретны.
  Сначала ищется исполнение с запасом и только потом впритык — узел, набитый до
  последнего гвоздя, не прощает ошибок монтажа.

### Подбор по минимальной стоимости

Кнопка «Минимальная цена» перебирает конструкцию целиком и выдаёт список
вариантов с U ≤ целевого запаса, отсортированный по стоимости материалов.

Полный перебор — десятки тысяч сочетаний. Цепочка почти однонаправленная
(кровля → прогон → столбы), поэтому поиск поэтапный:

1. по каждому числу стропил подбирается сначала обрешётка (её пролёт — шаг
   стропил, сечение стропила на неё не влияет), затем стропило под весом уже
   выбранной обрешётки;
2. несколько самых дешёвых кровельных вариантов идут дальше; для каждого
   наружный и стеновой ряды подбираются порознь (6 + 6 сочетаний вместо 36) —
   они связаны только через кровлю, которая к этому моменту уже посчитана;
3. собранный вариант проверяется целиком: отдельные проверки могли пройти,
   а огибающая — нет.

**Почему перебор снизу, а не двоичный поиск.** Сортамент упорядочен по расходу
материала (внутри материала это и есть порядок по цене: дерево считается по
объёму, металл по массе — и то и другое пропорционально площади сечения).
Несущая способность вдоль этого порядка не монотонна: 40×40×3 дороже 50×50×2,
но хуже её и по W, и по радиусу инерции; у 60×60×3 радиус инерции меньше, чем
у более дешёвой 60×60×2. Двоичный поиск такие «ямы» перешагивает и возвращает
сечение дороже нужного — так столбы у стены выходили 100×100×3 там, где
проходила 60×60×2. Перебор снизу возвращает первое прошедшее, то есть заведомо
самое дешёвое; заведомо слабые сечения (не лучше уже провалившегося ни по
одной характеристике: W, I, i, A_s в обеих плоскостях) пропускаются без счёта.

Чтобы перебор был не дороже двоичного поиска, на этапе опор считается только
сам ряд — балка и стойки под ней (`analyseLineBeam`, `analysePostRow`), а не
вся конструкция; нагрузки от кровли передаёт `supportLoads`, общая с полным
расчётом, — формулы распора не расходятся.

### Отчёт

Печатная форма / PDF: исходные данные, схемы, все проверки с формулами и числами,
спецификация материалов (м³ пиломатериала, кг металла, длины), примечания и ограничения.

В шапке отчёта — дата, **версия программы** и **ссылка на расчёт**: по распечатке вариант
открывается снова ровно таким, каким его посчитали, а по версии и `CHANGELOG.md` видно,
изменился ли с тех пор расчёт.

## 8. Архитектура

Стек: **чистый JavaScript (ES-модули) + SVG, без зависимостей.** Ни фреймворка, ни
бандлера, ни npm-пакетов: нужен только Node 22 для тестов и сборки. Сборка — статика,
работает офлайн, с GitHub Pages и при открытии `index.html` двойным кликом.

> Черновик этой спецификации предполагал TypeScript + Vite + React + zustand + Vitest.
> От этого отказались в пользу проекта без зависимостей: одна страница, которая
> открывается где угодно и не устаревает вместе с пакетами.

## 9. Границы применимости (пишем в отчёт)

Не считаем: двускатные и арочные навесы, подкосы до земли (из связей считаются крест в ряду
и диагонали в плоскости кровли), снеговые нагрузки на неровных кровлях, огнестойкость,
расчёт основания по грунту,
сейсмику, температурные воздействия.

Элемент с куском меньше чем на двух опорах при стыке встык — изменяемая схема: он не
проверяется вовсе (U = ∞), а нагрузка с него передаётся дальше по неразрезной схеме, какой
он станет со стыком на накладке. Числа прочих элементов в таком расчёте — оценка на случай,
когда стык исправят, а не проверка того, что нарисовано.

Результат — инженерная оценка для частного строительства, а не проект,
прошедший экспертизу.
